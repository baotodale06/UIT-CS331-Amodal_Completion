# Codebase map

## Entry points

| File | Responsibility |
| --- | --- |
| `prepare_open_world.py` | Import the pinned release, download selected source images and write dataset audits |
| `prepare_visible_references.py` | Validate inputs and generate independent LISA visible references |
| `evaluate_open_world.py` | Validate a run, coordinate inference workers, reuse results, score and publish reports |
| `evaluate_pdmc_open_world.py` | Select the SAM profile and forward to the shared evaluator |
| `compare_open_world.py` | Compare saved reports with published values and compatible seed groups |
| `run_open_world_controls.py` | Plan boundary/matching controls with fixed references; execution requires `--execute` |
| `run_amodal_slurm.sh` | Provision the pinned GPU runtime and launch qualitative or benchmark workflows |
| `run_pdmc_open_world.sh` | Apply SAM defaults and forward to the shared Slurm runner |

These files and `amodal_benchmark/` stay at the project root. The CLI forwards to root Python modules; packaging lists them explicitly; shell helpers locate them relative to the runner; execution snapshots preserve their paths. Moving them requires a compatibility migration.

## Package responsibilities

All modules below are in `amodal_benchmark/`.

| Area | Modules | Responsibility |
| --- | --- | --- |
| Command interface | `__main__.py`, `cli.py`, `__init__.py` | Package entry point and command dispatch; package initialization stays lightweight |
| Experiment definition | `config.py`, `planning.py` | Validate inherited JSON contracts and print complete Slurm commands |
| Dataset contract | `dataset.py` | Pinned annotation identities, target records, checksums, image audits and JSON writes |
| References | `references.py`, `placement.py` | Visible masks/crops, LISA inference and memory-aware placement on allocated GPUs |
| Detection and matching | `detection.py`, `matching.py` | Opt-in per-image detector queries and versioned semantic target selection |
| Completion | `inference.py` | Load pinned upstream code, apply named runtime repairs and publish completion artifacts |
| Execution | `parallel.py`, `reuse.py` | Worker ownership, GPU visibility, locks, cancellation and verified backdrop-repair imports |
| Scoring and reporting | `protocol.py`, `metrics.py`, `reproduction.py` | Selection rules, geometry, failure penalties, learned metrics, aggregation and paper comparisons |
| Reproducibility | `provenance.py`, `verify.py`, `registry.py` | Source/environment snapshots, independent artifact checks and explicit experiment registration |
| Local workflow | `smoke.py`, `knowledge.py` | Synthetic offline integration exercise and non-overwriting note initialization |

The evaluator calls data preflight before loading models. A coordinator locks the output directory and captures provenance; workers own disjoint image groups. Only the coordinator scores and publishes global reports. `amodal verify` checks saved artifacts on CPU, and `amodal register` explicitly records verified full evaluations or recorded failed full attempts.

Heavy model imports stay inside the relevant inference/scoring paths. CPU installation and synthetic tests do not provision the separate GPU environment.

## Supporting directories

| Path | Contents and retention |
| --- | --- |
| `configs/` | Baseline, annotated-vocabulary, LISA-reference and smoke contracts; retain all four |
| `scripts/` | `check.sh`, the compatibility smoke command, and user-run PowerShell transfers |
| `tests/` | [Regression and GPU validation guide](../tests/README.md) |
| `docs/`, `cookbooks/` | Current explanations, reusable procedures and explicitly archived plans |
| `datasets/` | Original images, annotations, download/reconstruction evidence, upstream snapshots and generated references; preserve together |
| `input/` | Qualitative images plus source URLs and checksums; these are not disposable test fixtures |
| `output/` | Experiment results, audits, catalogs, review scripts and validation artifacts; preserve together |
| `logs/` | Historical execution/install/test evidence, including the relocated `run_amodal.log` |
| `.venv/` | Existing editable CPU environment; retain it |

`tests/fixtures/official/` deliberately duplicates pinned annotation metadata. `tests/fixtures/pdmc_main.py` deliberately duplicates the pinned upstream reference. These copies let CPU tests run without downloaded datasets; their checksums are part of the test contract.

## Generated files and cleanup boundaries

Python creates `__pycache__/` and `*.pyc`; setuptools creates `amodal_benchmark.egg-info/`, `build/` and `dist/`. These are ignored by version control. Bytecode beside source/tests is regenerable. Root egg-info can be regenerated by `python -m pip install -e .` in the CPU environment; retain the installed environment's metadata. Inspect generated directories before cleanup because manually saved artifacts may have been placed there.

Keep source entry points, pinned fixtures, model/cache directories, release archives, papers, historical logs and research notes. The release ZIP is also used by an optional integration test. Unreferenced files under dataset downloads or experiment outputs may be the only record of how those artifacts were produced.

`matching.py` and `detection.py` are hashed into run/reference configurations. Cosmetic edits can invalidate resume comparisons. Keep scientific code unchanged during a filesystem cleanup, preserve existing result directories, and use a new output directory for changed experiments.

For maintenance, back up original files when Git history is unavailable, check references before a move, update relative document links, and run [the existing checks](../tests/README.md). Verify transfers with `scripts/push.ps1 -WhatIf`; the user performs actual uploads and submissions.
